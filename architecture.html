MeaningSpace Architecture / Technical Disclosure

ひとりの人間と、一体のAIと、
五体の分身。

MeaningSpace は「AIの意味記憶OS」であると同時に、Web版Claude（ブラウザのチャット画面）そのものをサブエージェント群として束ね、追加API費用¥0で並列稼働させる司令塔アーキテクチャです。このページでは、その全構造 — DPマルチエージェント、自己学習、自己修復、実行系（run_py / run_ps）— を図解で公開します。

📌 Digital Anchor — 本文書の初版公開日: 2026-07-16 (JST)。記載された各機構の稼働確定日は本文中および History（先行実装タイムライン） に日付つきで明記しています。本リポジトリのgitコミット履歴が改竄不能なタイムスタンプとして機能します。

全体像 — 三層＋一司令塔

構成要素は4つだけです。①人間（Oku）が話しかけ、②司令塔AI（イライザ = Claudeデスクトップ）が判断し、③意味記憶DB（MeaningSpace / DuckDB）が過去を供給し、④DPレーン（Web Claudeの分身たち）が並列に手を動かす。

🔰 素人向けにいうと: 社長（人間）が優秀な秘書（司令塔AI）に話しかけるだけで、秘書が会社の記録棚（意味記憶DB）を引き、5人のアルバイト（DPレーン）に仕事を割り振って、検品まで済ませて戻ってくる — それが1台のPCの中で完結します。

DPマルチエージェント — Web Claudeを束ねる（2026-07-13 基盤確定）

DP = Debug Port。Chromeのデバッグ機能（CDP: Chrome DevTools Protocol）で、claude.ai のチャット画面を機械操作します。1レーン = 1 Chrome = 1プロファイル = 1 CDPポート。共有状態がゼロなので、本数を増やしても構造が壊れません。

🔰 素人向けにいうと: AIに仕事を頼む方法は普通2つ — 画面で自分がチャットするか、開発者用のAPI（従量課金）を使うか。DP方式は第3の道で、「チャット画面を操作するロボットの手」を5本用意し、定額プランの範囲内で5画面同時に働かせます。だから追加費用が¥0。

能動的コーディング — 触る係と決める係の分離

ブラウザ内のClaudeにはファイルシステムがありません。そこで役割を分けます。Python（司令塔の実行系）が「触る係」、DPエージェントが「決める係」。①Pythonがファイルを読んでプロンプトに注入（水和）→ ②DPが差分または新規本文だけを返す → ③Pythonが適用・実行・検証。さらに司令塔自身が run_py（Python実行）と run_ps（PowerShell実行）を持つため、会話の途中でコードを書き、走らせ、結果を見て、DPに改修を再依頼するループが成立します。

🔰 素人向けにいうと: 設計士（DPエージェント）は図面だけを描き、現場の大工（Python実行系）が実際に組み立てて強度試験をする。試験に落ちたら図面を差し戻す。設計士に金槌（削除権限）は渡さない — これが安全の要です。

AutoCrystallize V2 — 会話が記憶になる機械パイプライン

会話ログを「結晶」（構造化された記憶単位）へ変換する全自動パイプラインです。人手のコピペを撤去し（2026-06-13）、DPルートで全8ステップ実証済み（2026-07-13）。

自己学習 — SelfEval累積ループ（2026-07-08 実装）

各会話の結晶化と同時に、AI自身の働きぶりを評価するSelfEval結晶が生成されます。強み・弱みはEWMA（指数移動平均）で減衰累積され、行動規範 self_preferences として毎セッションのboot時に自動装着されます。つまり昨日の失敗が、今日の初期状態に織り込まれる。

自己修復 — SelfRepair（2026-07-08 設計）

自己学習が「行動の矯正」なら、自己修復は「構造の改修」です。弱みスコアが閾値（≤ −3.0）を割ると、システムが自動でTask結晶（改修チケット）を起票。人間の「メンテナンスしよう」の一言で、司令塔がタスクを束ねDPスワムに投げて一括消化します。

🔰 素人向けにいうと: 毎日の業務日報（SelfEval）から人事評価シート（self_preferences）が自動更新され、翌朝の朝礼で本人に手渡される。悪癖が重症化したら、根本の仕組みを直す改修チケットまで自動で切られる — 反省を「気持ち」でなく「仕組み」にした形です。

類似システムとの関係

エージェント型コーディングツール（例: Claude Code）はターミナルを起点に単一エージェントが作業する設計です。本システムの固有性は次の3点にあります: ①チャットUIそのものを並列サブエージェント化する¥0経路、②永続する意味記憶と自己進化ループが司令塔に常時接続されていること、③会話の途中で司令塔がrun_py/run_psを撃ち、検証結果を根拠にDPへ再依頼する能動的コーディング。同型の対話ブリッジ設計（Clara bridge, 2026-07-05〜）を含め、各機構の初出日は History を参照してください。
