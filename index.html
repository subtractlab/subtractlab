The common belief

AI gets smarter
by adding.

Bigger models. Longer context. More memory. Progress in AI is assumed to mean adding.

So memory systems keep stacking summaries, adding notes and widening what they search.

The crack

The more it remembers,
the more it gets lost.

Work with an AI every day and every new session starts from zero again.

  • Summarize and discardIt fits in context — but why a decision was made is gone. When your understanding changes, there is nothing to go back to.
  • Reload everythingNothing is lost — but every question costs more reading, more time and more of your usage limit.
  • Keep adding notesNobody can tell which notes still hold and which were overturned.
The turn

Subtract,
and meaning remains.

Keep every word. Carry only the meaning. That is MeaningSpace.

Everything lives in one local DuckDB file, so a single query walks from meaning to section, to the original line, to a file, to the reason it changed.

MeaningSpace in detail　3Gravity　QIS　Architecture

Ground — the logs

Every conversation is kept whole, line by line, and never rewritten.

Crystals — the meaning

Each conversation is split into sections, each marked decided, overturned or open, with an address back to its lines.

Skills — procedures that light up

Procedures are crystals too. Only when a task is close enough does a skill’s title arrive.

Map — where things are

The present state of every file, and a reason and a reverse patch for every change, tied to the conversation.

How it is built

No terminal.
No IDE.
No Claude Code.

Everything here — this site included — is built by talking to Claude in the chat app.

The chat app connects over MCP (server-sent events) to a proprietary environment. That server gives the AI its tools: read, write, search and replace files; do the work; search the meaning space; generate images, search the web, read videos.

On 2026-10-25 the same change was made both ways. Claude Code was faster at searching code and finding holes; MeaningSpace was better at context. So the server gained regex search and exact-match replace. What remains is the difference in context.
